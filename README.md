# Rag-Chat

RAG-пайплайн для чата поддержки банка и стенд, который **измеряет каждый шаг**: какой поиск лучше (BM25, dense, hybrid), и помогает ли маршрутизация по теме. Всё работает локально (ollama, `bge-m3`, `qwen3.5`), без платных API.

Продолжение гипотезы из [agentic-memory](https://github.com/Mephias13/agentic-memory): там роутинг по сущности спасал recall при росте хранилища, но на 8 вопросах на точку. Здесь та же идея проверяется на данных, близких к чату поддержки, с доверительными интервалами. **Результат: здесь гипотеза не подтвердилась** (см. ниже).

## Данные

- **База знаний:** 100 статей fincult.info («Финансовая культура», проект Банка России), 5 тем по 20: `refunds` (списания, возвраты, навязанные услуги), `credits`, `cards`, `payments` (переводы, счета, вклады), `fraud`. Тексты в репозитории **не хранятся**: список в [kb_urls.tsv](kb_urls.tsv), скачивает [fetch_kb.py](fetch_kb.py) из JSON-API сайта. Нарезка: 1731 чанк до 800 символов, заголовок статьи добавлен в каждый.
- **Вопросы:** 83 штуки в [questions.jsonl](questions.jsonl). Черновики сгенерированы qwen3.5:9b по тексту статей (по одному на статью), затем отфильтрованы вручную от двусмысленных (на которые могли ответить две-три статьи) и от вопросов с неверной статьёй-ответом; два переписаны (`source: llm+edited`). У 17 статей вопросов нет, они остаются в базе как отвлекающие. Эталон: одна статья на вопрос, тема вопроса = тема его статьи.

## Как устроено

```
fetch_kb.py   JSON-API fincult.info -> data/kb/<тема>/<статья>.md
kb.py         чанки (<=800 символов) и токены (lowercase, ё->е, snowball-стемминг)
retrieval.py  BM25 (сырой / со стеммингом) | dense (bge-m3, кэш на диск) | hybrid = RRF(BM25 stem, dense)
              чанки -> статьи по лучшему чанку
router.py     тема обращения: LLM zero-shot (qwen3.5:4b) | TF-IDF (char n-gram) + LogisticRegression
evaluate.py   hit@1, hit@5, MRR@10, bootstrap 95% CI -> results.md, results.json
ask.py        демо: топ-3 статьи -> ответ qwen3.5:9b со ссылками на источники
```

## Выводы

1. **Жёсткий роутинг вредит.** Если тема выбрана неверно, нужной статьи в пуле нет, поэтому recall получается примерно равным точности роутера: 0.64 у LLM-роутера против 0.95 у плоского поиска. Грубая оценка из таблиц: чтобы сравняться с плоским поиском при потолке 0.99, роутер должен быть точен примерно на 96%.
2. **Даже идеальный роутер почти ничего не даёт**: +0.04 по hit@5 на 100 статьях, интервал касается нуля. Плоский поиск при росте базы с 40 до 100 статей не деградирует (0.97, 0.98, 0.95), то есть режима, где роутинг помогает, в этом диапазоне нет.
3. **dense и hybrid лучше BM25**; hybrid от dense на этих данных статистически не отличается.
4. **LLM-роутер точнее TF-IDF на 12 пунктов, но интервалы пересекаются, и он примерно в 1600 раз медленнее** (2.5 с против 1.5 мс).

Что стоит проверить дальше: мягкий роутинг (откат на плоский поиск при низкой уверенности, или поиск по двум темам) и гораздо большую базу.

## Ограничения

- **83 вопроса**, интервалы широкие; в E3 на 40 статьях всего 34 вопроса, подвыборка статей одна (seed 0).
- **Вопросы сгенерированы моделью по тексту статей** и отфильтрованы от двусмысленных, поэтому метрики оптимистичнее, чем в реальном чате. Эталон одна статья, хотя на вопрос могут отвечать несколько.
- **Темы заданы вручную**, тема `payments` смешанная (переводы, вклады, QR, счета): LLM-роутер угадал 4 из 16, TF-IDF 2 из 16. Часть ошибки роутера это размытость тем. LLM-роутер не настраивался (один zero-shot промпт).
- **fincult.info общеобразовательный сайт**, а не справочный центр банка.
- **Латентность** измерена на RTX 4060 Laptop (8 ГБ). Ollama на Windows может после перезапуска молча стартовать на CPU, поэтому `evaluate.py` проверяет `size_vram == size` перед замером роутера.
- **`ask.py` не оценивался**, роутинг в нём не используется, порога уверенности нет: на вопрос вне базы модель отказывается отвечать, но источники всё равно перечисляются.

## Запуск

```bash
python -m venv .venv && .venv/Scripts/activate        # Windows
pip install -r requirements.txt
ollama pull bge-m3 && ollama pull qwen3.5:4b && ollama pull qwen3.5:9b

python fetch_kb.py                                    # скачать статьи в data/kb
python evaluate.py                                    # E1-E3 -> results.md, results.json
python ask.py "Заказала обувь, пришла не та, магазин не возвращает деньги"
python -m pytest tests                                # тесты не требуют ollama
```

Порт ollama задаётся переменной `OLLAMA_URL` (по умолчанию `http://localhost:11434`). `make_questions.py` создаёт черновики вопросов; готовый отфильтрованный набор уже лежит в `questions.jsonl`.
